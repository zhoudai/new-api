## 1. 系统对象和职责

| 对象 | 作用 | 凭证由谁保管 |
| --- | --- | --- |
| 平台管理员 | 配置渠道、模型、分组、用户、额度和审计 | 平台管理方 |
| 业务项目 | 使用 AI 能力的业务系统 | 项目后端团队 |
| 企业/用户账号 | 保存余额并承担模型调用费用 | 平台管理员和企业负责人 |
| 项目凭证 | 项目后端访问 bridge 的凭证 | 项目后端 Secret |
| 企业内部 New API Key | bridge 代表某个企业向 New API 扣费 | 平台 Secret 或 bridge 配置 |

推荐关系：

~~~text
平台管理员
  ├─ 项目 A
  │    ├─ 企业 A1 -> 独立用户、余额和内部 New API Key
  │    └─ 企业 A2 -> 独立用户、余额和内部 New API Key
  └─ 项目 B
       └─ 企业 B1 -> 独立用户、余额和内部 New API Key
~~~

必须遵守：

- 一个付费企业使用一个独立计费账号，不与其他企业共用余额。
- 业务项目只保存项目凭证，不保存上游模型 Key 或企业内部 New API Key。
- 测试环境、生产环境和不同项目使用不同凭证。
- 平台只接入合法取得并允许当前服务场景使用的上游模型服务。

## 3. 首次部署平台

在部署主机执行：

~~~bash
cd <PROJECT_ROOT>
docker compose up -d
docker compose ps
curl --noproxy '*' <PLATFORM_BASE_URL>/api/status
~~~

确认平台、数据库和缓存服务正常后，在浏览器打开：

~~~text
<PLATFORM_BASE_URL>/setup
~~~

按顺序完成：

1. 检查数据库。
2. 设置平台管理员账号和密码。
3. 选择企业/多用户运行模式。
4. 完成初始化并登录后台。

生产部署必须在 Secret 管理器中保存密码、数据库凭据、Redis 凭据、会话密钥和上游 API Key，不得写入本文档或 Git。

## 4. 配置上游模型渠道

1. 打开 <PLATFORM_BASE_URL>/channels。
2. 点击新增渠道。
3. 选择上游服务商，填写 Base URL、模型名称和上游 API Key。
4. 保存渠道。
5. 点击渠道测试，确认成功后再开放给企业使用。

上游 API Key 只保存在平台服务端。业务项目不得直接连接上游服务商。

## 5. 配置模型价格和分组价格

### 5.1 模型基础价格

打开 <PLATFORM_BASE_URL>/system-settings/billing/model-pricing，为每个模型填写官方价格和平台销售价格。

推荐把模型基础价格和活动优惠分开：

~~~text
正常基础价格 = 官方峰值价格 × 正常加价倍数
活动最终价格 = 正常基础价格 × 活动分组倍率
~~~

### 5.2 分组配置

打开 <PLATFORM_BASE_URL>/system-settings/billing/group-pricing：

| 分组 | 模型/调用倍率 | 充值倍率 | 用途 |
| --- | ---: | ---: | --- |
| default | 1 | 1 | 正常价格 |
| activity | <CAMPAIGN_GROUP_RATIO> | 1 | 活动价格 |

如果正常基础价格为官方峰值价格的 2 倍，活动目标为官方峰值价格的 1.5 倍：

~~~text
活动分组倍率 = 1.5 ÷ 2 = 0.75
~~~

充值倍率不要承担模型优惠，也不要用充值倍率模拟充值赠送。充值优惠和模型优惠同时启用前，应先计算最终销售价格，避免优惠叠加。

### 5.3 活动启停

当前接入方式不包含按日期自动切换活动组。

活动开始时：

1. 在用户管理中找到目标企业账号。
2. 将企业账号或其 API Key 分配到 activity。
3. 用测试请求确认扣费价格正确。

活动结束时，将目标企业账号或 API Key 改回 default。不要删除 activity 分组，以免影响历史记录或仍在使用的 Key。

## 6. 接入一个新的业务项目

当前 bridge 采用配置驱动方式，一个 bridge 进程绑定一个项目标识。新增项目时，不要覆盖已有项目的 bridge 配置。

### 6.1 准备标识

| 信息 | 示例格式 | 说明 |
| --- | --- | --- |
| 项目标识 | project-example | 项目级唯一标识 |
| 项目凭证 | <PROJECT_CREDENTIAL> | 项目后端调用 bridge |
| 企业标识 | enterprise-example | 项目内付费主体唯一标识 |
| 功能标识 | feature-example | 业务功能唯一标识 |

项目标识、企业标识和功能标识只能使用字母、数字、-、_、.、:，长度最多 64 个字符，并且必须以字母或数字开头。

### 6.2 创建企业/用户账号

对项目中的每个付费企业重复以下步骤：

1. 打开 <PLATFORM_BASE_URL>/users。
2. 创建普通用户账号，用户名使用企业内部编号或简称。
3. 不要给企业账号管理员权限。
4. 通过人工调整额度或兑换码增加余额。
5. 建立企业标识与用户账号的内部登记关系。

一个企业一个计费账号。不要让多个企业共用一个余额账号，否则平台无法准确核算和对账。

### 6.3 创建企业内部 New API Key

这个 Key 只用于 bridge 代表企业向 New API 扣费，不能交给业务项目或终端用户。

1. 以企业账号登录 <PLATFORM_BASE_URL>/keys。
2. 创建企业应用 Key。
3. 名称写清楚企业、项目和环境，例如 enterprise-example-project-example-production。
4. 设置模型限制、额度、过期时间和 IP 白名单。
5. 选择 default 或 activity 分组。
6. 将完整 Key 交给平台管理员，通过 Secret 管理器注入 bridge。
7. 不要把这个 Key 放进业务项目代码、浏览器、小程序或前端环境变量。

### 6.4 生成项目凭证

项目凭证与企业内部 New API Key 不同。平台管理员在安全环境中生成随机值：

~~~bash
openssl rand -hex 32
~~~

将结果分别保存到：

- bridge 的 AI_BRIDGE_PROJECT_KEY；
- 业务项目后端的 Secret。

不要把项目凭证放到浏览器、小程序、移动端、前端环境变量或公开仓库。

### 6.5 配置项目 bridge

复制模板：

~~~bash
cd <PROJECT_ROOT>
cp bridge/.env.example bridge/.env.local
~~~

填写以下配置。真实值只允许出现在本机忽略文件或 Secret 中：

~~~dotenv
AI_BRIDGE_PROJECT_ID=project-example
AI_BRIDGE_PROJECT_KEY=<PROJECT_CREDENTIAL>
AI_BRIDGE_ENTERPRISE_TOKENS=enterprise-example=<ENTERPRISE_NEW_API_KEY>
~~~

同一个项目有多个企业时，每行配置一个映射：

~~~dotenv
AI_BRIDGE_ENTERPRISE_TOKENS="enterprise-a=<ENTERPRISE_A_NEW_API_KEY>
enterprise-b=<ENTERPRISE_B_NEW_API_KEY>"
~~~

企业标识必须唯一，且必须与业务请求头中的 X-AI-Enterprise-Id 完全一致。

### 6.6 启动和检查 bridge

~~~bash
cd <PROJECT_ROOT>
docker compose --env-file bridge/.env.local --profile bridge up -d --build project-bridge
curl --noproxy '*' <BRIDGE_BASE_URL>/health/ready
~~~

健康检查应返回：

~~~json
{"status":"ready"}
~~~

## 7. 多个项目同时接入

当前一个 bridge 进程只绑定一个项目。多个项目同时运行时，为每个项目单独部署 bridge 实例：

| 项目 | bridge 实例 | 对外端口 | 项目标识 |
| --- | --- | ---: | --- |
| 项目 A | 独立实例 A | <PORT_A> | <PROJECT_ID_A> |
| 项目 B | 独立实例 B | <PORT_B> | <PROJECT_ID_B> |

新增实例时，复制 Compose 中的 bridge 服务配置，只修改：

1. 服务名和容器名。
2. 宿主机对外端口。
3. 项目对应的 AI_BRIDGE_PROJECT_ID、AI_BRIDGE_PROJECT_KEY 和 AI_BRIDGE_ENTERPRISE_TOKENS 环境变量。

不要通过覆盖已有项目的环境变量来接入新项目。

## 8. 业务项目调用格式

业务项目后端调用 bridge，不调用 New API 内部地址：

~~~bash
curl <BRIDGE_BASE_URL>/v1/chat/completions -H 'Authorization: Bearer <PROJECT_CREDENTIAL>' -H 'Content-Type: application/json' -H 'X-AI-Project-Id: project-example' -H 'X-AI-Enterprise-Id: enterprise-example' -H 'X-AI-Feature: feature-example' -H 'X-Request-Id: <REQUEST_ID>' -d '{"model":"<MODEL_NAME>","messages":[{"role":"user","content":"请输出测试结果"}],"stream":false}'
~~~

请求头说明：

| 请求头 | 内容 | 是否必填 |
| --- | --- | --- |
| Authorization | 项目凭证 | 是 |
| X-AI-Project-Id | 项目标识 | 是 |
| X-AI-Enterprise-Id | 当前企业标识 | 是 |
| X-AI-Feature | 当前业务功能标识 | 是 |
| X-Request-Id | 项目侧请求号 | 否 |

bridge 会根据企业标识映射到企业内部 New API Key，并替换上游认证信息。项目凭证不会透传给 New API 或上游模型。

## 9. 接入验收清单

每接入一个项目，必须逐项确认：

- [ ] 平台、数据库、缓存和 bridge 健康。
- [ ] 上游渠道测试成功。
- [ ] 项目标识、企业标识和功能标识符合格式要求。
- [ ] 每个企业有独立用户账号、余额和内部 New API Key。
- [ ] 项目凭证与企业内部 New API Key 没有混用。
- [ ] 项目后端没有保存上游模型 Key。
- [ ] 正常组和活动组的价格计算结果符合销售策略。
- [ ] 充值倍率没有被用于模拟模型优惠或赠送余额。
- [ ] 测试请求能在平台日志中按项目、企业、模型和请求号追溯。
- [ ] 余额扣减、失败请求和重复回调符合预期。

## 10. 常见错误

| 现象 | 处理方法 |
| --- | --- |
| bridge 健康检查失败 | 检查容器状态和 bridge 日志 |
| HTTP 401 | Authorization 应填写项目凭证，不是企业内部 New API Key |
| HTTP 403 | 检查企业标识是否已配置映射、是否有额度 |
| HTTP 400 | 检查项目、企业和功能标识格式 |
| HTTP 404 | 请求路径必须是 /v1/* |
| 余额没有扣减 | 检查企业映射、Key 分组和平台日志 |
| 价格不正确 | 检查模型基础价格、分组倍率和 API Key 所属分组 |
| 新项目导致旧项目不可用 | 说明覆盖了旧项目 bridge 配置，应恢复旧配置并为新项目建立独立实例 |

通用日志命令：

~~~bash
cd <PROJECT_ROOT>
docker compose logs --tail=100 project-bridge
docker compose logs --tail=100 new-api
~~~

排错时可以使用项目标识、企业标识、功能标识和请求号；不要打印完整凭证、密码、数据库连接串或支付信息。

## 11. 安全与敏感信息检查

### 11.1 禁止写入本文档的内容

- 真实密码、API Key、项目凭证、Secret 和 Cookie。
- 数据库 DSN、Redis 连接串和支付渠道密钥。
- 个人电脑绝对路径、内网 IP、真实域名和服务器主机名。
- 企业真实名称、联系人、手机号、邮箱和客户数据。
- 包含请求内容、Authorization 或完整 Key 的日志片段。

### 11.2 发布前检查

~~~bash
rg -n -i "password|secret|api[_ -]?key|authorization|bearer|postgresql://|redis://|sk-|/Users/|127.0.0.1|localhost" docs/ bridge/.env.example
~~~

检查结果必须满足：

- 只能出现字段名、占位符和安全说明。
- 不得出现真实凭证、真实地址或客户资料。
- .env.local、数据库目录和日志目录不得提交 Git。

## 12. 当前实现边界

本标准流程覆盖：平台部署、上游渠道、模型定价、企业账号、项目 bridge、企业 Key 映射、API 调用和扣费审计。

项目统一入口、服务端调用和正式 SSO 的边界见 [`项目统一接入协议-v1.md`](项目统一接入协议-v1.md)。当前 `sourceProject`、`returnTo` 仅用于普通导航，不能代替平台鉴权。

以下能力需要单独设计和验收，不能默认视为已有：

- 动态项目登记和后台配置。
- 活动开始/结束时间及自动切换。
- 自动“支付固定金额到账额外赠送额度”的独立账本。
- 真实支付、自动退款和财务对账。
- 企业内部成员邀请、角色授权和管理员转移。
