# 项目凭证管理

项目凭证只供业务项目后端调用 bridge；企业用户名和密码用于登录平台充值与账单页面。企业内不建立个人计费账户，本期不要求免密 SSO 或项目用户映射。

## 管理 API

以下路径相对于平台地址。管理端使用平台管理员登录后的 `Authorization: Bearer <ADMIN_ACCESS_TOKEN>`；请求体为 JSON。普通企业账户和项目凭证均不能调用管理接口。

| 方法与路径 | 请求 | 返回 |
| --- | --- | --- |
| `POST /api/project-credentials` | `{"project_id":"project-example"}` | `data.credential` 状态与 `data.secret` 新凭证 |
| `GET /api/project-credentials?after=0` | 无 | `data` 状态数组，每页最多 100 条，以最后一条 `id` 作为下一页 `after` |
| `POST /api/project-credentials/project-example/rotate` | `{"version":1}` | 新状态与新凭证，旧凭证立即失效 |
| `POST /api/project-credentials/project-example/disable` | `{"version":2}` | 禁用后的状态，不返回凭证 |
| `GET /api/project-credentials/audits?after=0` | 无 | 审计数组，每页最多 100 条，包含凭证 ID、操作者、动作、版本、时间 |

项目标识限小写字母、数字、`-_.:`，以字母或数字开头，最多 64 字符。每个项目保存一个当前凭证；环境应使用不同项目标识。状态查询包含 `id`、`project_id`、`version`、`status`、`created_at`、`updated_at`，不返回明文或摘要。

凭证使用密码学随机数生成，只在创建/轮换响应中展示一次。请立即保存到项目后端 Secret；响应丢失只能轮换。修改需提交当前 `version`，版本冲突或项目不存在返回 `409`；参数错误返回 `400`，数据库不可用返回 `503`。禁用后可通过当前版本轮换恢复使用。

凭证和审计在主数据库同一事务写入；审计失败时变更回滚。不依赖独立消费日志库。新表为 `project_credentials` 和 `project_credential_audits`，由平台启动迁移创建。

## bridge 切换

1. 平台管理员通过上述 API 生成项目凭证，并交给项目后端保管。企业内部 New API Key 仍由平台保管，企业映射仍使用 `AI_BRIDGE_ENTERPRISE_TOKENS`。
2. 在 bridge 配置中设置 `AI_BRIDGE_CREDENTIAL_VERIFY_URL`，指向受信任平台的 `/api/project-credentials/verify`。同一 Compose 网络可用 `http://new-api:3000/api/project-credentials/verify`；跨主机使用 HTTPS。
3. 项目后端更新项目凭证后，按[部署说明](部署与凭据说明.md)重建 bridge。每次调用先在线校验项目标识与凭证，再进行企业映射和上游转发。

校验接口：`POST /api/project-credentials/verify`，请求头为项目凭证 `Authorization: Bearer <PROJECT_CREDENTIAL>` 和 `X-AI-Project-Id`；有效返回 `204`，无效/禁用返回 `401`，数据库故障返回 `503`。

在线校验不缓存成功结果、不跟随重定向，超时或平台故障拒绝调用。托管模式下即使仍配置 `AI_BRIDGE_PROJECT_KEY`，也不会回退使用。未配置校验地址的旧实例仍是环境变量 POC 模式，不受平台禁用/轮换控制；需要逐实例切换。

轮换后应立即更新项目后端 Secret。已经通过校验的在途请求可继续完成；后续校验使用新版本。轮换不提供旧凭证宽限期。

## 验收

用同一项目依次验证：新凭证可调用、其他项目标识被拒绝、轮换后旧凭证被拒绝、禁用后新凭证被拒绝、平台校验故障时不向模型转发。状态和审计查询不得出现凭证明文或摘要。

当前交付为管理 API 与 bridge 接入能力；未提供新的管理页面。模型调用、扣费及企业映射规则见[统一接入协议](项目统一接入协议-v1.md)。

## 开发验证

在仓库根目录运行（MySQL/PostgreSQL DSN 指向独立测试库）：

```bash
CGO_ENABLED=0 go test ./model ./controller ./bridge ./router -run 'TestProjectCredential|TestManagedCredential' -count=1 -v
```

模型测试从 `TEST_MYSQL_DSN`、`TEST_POSTGRES_DSN` 读取测试连接；未设置时会明确跳过相应数据库，不能视为三库通过。测试使用隔离表前缀，保留结果供复核。凭证新表重复迁移验证不等于最新发布版完整数据库升级验收；发布前仍须补齐该门禁。

本轮验证：SQLite 3.50.4、MySQL 8.4.11、PostgreSQL 15.19 的凭证生命周期与新表重复迁移均通过；API 响应、项目凭证无管理员权限、实际路由鉴权及 bridge 拒绝回退测试通过。尚缺最新发布版数据库升级样本，未验证完整升级，也未切换现有运行实例。
