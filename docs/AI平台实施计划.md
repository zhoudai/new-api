# AI 平台实施计划

## 目标

在独立项目中基于 New API 建立可被多个业务项目复用的 AI 能力中转平台，先验证最小闭环：

```text
企业账户 -> 人工充值/兑换码 -> 额度 -> 项目 API Key -> 模型调用 -> 用量与扣费审计
```

## AGPLv3 合规门禁

- New API 允许在遵守 AGPLv3 的前提下用于商业收费服务。
- 修改 New API 并通过网络提供服务时，向交互用户提供修改版本对应源码。
- 修改后的界面保留 `Frontend design and development by New API contributors.`、版权声明和可见原项目链接，并标注修改内容。
- 源码发布包不得包含 API Key、数据库密码、客户数据或支付敏感配置。
- 若要求闭源修改、完全去品牌或白标分发，先取得商业授权或切换其他网关。

## 依赖与边界

- 上游模型必须是平台合法取得并允许当前服务场景使用的官方 API。
- `edu-training`、`hedezhongcheng` 等项目只通过服务端 API 接入。
- `session + Flint`、业务权限、数据查询、脱敏、结构化结果和图形展示由接入项目独立负责。
- 不采用订阅账号池化、拼车或未经授权的账号转售路径。

## 当前不做

- 不接真实支付渠道。
- 不改 New API 的业务能力核心；本轮仅保留跨项目审计请求号所需的 middleware 适配。
- 不将平台数据库接入现有招聘或培训业务数据库。
- 不把一次模型返回成功写成业务 AI 能力已完成。
