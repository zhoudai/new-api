# AI 平台项目统一接入协议 v1

## 1. 结论

接入 `ai-platform` 不会自动修改业务项目，也不会自动产生“AI 账户”入口或 SSO。

每个业务项目必须完成一次显式登记和适配：

- 服务端通过项目凭证调用 AI 网关；
- 项目自己的页面提供“AI 账户”入口；
- 平台侧按已登记的项目、企业和用户映射处理额度与权限。

当前已完成服务端 API 契约、普通跳转入口和第一版 SSO 授权码接口；普通跳转参数不能当作登录凭证。

## 2. 服务端调用契约

业务项目后端只能调用 bridge 的 `/v1/*`，不能调用上游模型或向客户端下发平台 Key。

必填请求头：

| 请求头 | 来源 | 规则 |
| --- | --- | --- |
| `Authorization` | 项目后端 Secret | 项目凭证，不能是企业内部 New API Key |
| `X-AI-Project-Id` | 项目配置 | 必须是已登记的项目标识 |
| `X-AI-Enterprise-Id` | 项目服务端会话/业务权限 | 不能直接信任客户端自报值 |
| `X-AI-Feature` | 项目服务端固定能力 | 必须是已登记的功能标识 |

可选请求头 `X-Request-Id` 用于跨项目和平台日志关联。bridge 会将其适配为 New API 识别的 `X-Oneapi-Request-Id`，平台根据项目和企业映射内部计费账户，内部 Key 不返回给业务项目。

## 3. 项目侧账户入口

当前 POC 允许项目生成以下普通跳转：

```text
<PLATFORM_BASE_URL>/wallet?sourceProject=<PROJECT_ID>&returnTo=<REGISTERED_RETURN_URL>
<PLATFORM_BASE_URL>/usage-logs/common?sourceProject=<PROJECT_ID>&returnTo=<REGISTERED_RETURN_URL>
```

平台必须将 `sourceProject` 和 `returnTo` 视为导航上下文，不得据此建立登录状态、企业权限或余额权限。`returnTo` 只能使用项目登记时的精确 HTTPS Origin 和路径白名单，不能接受任意外部地址。

## 4. 正式 SSO 第一版协议

当前实现采用“平台登录会话签发一次性授权码，项目后端兑换身份并建立自己的会话”的流程：

```text
平台已登录用户
  -> 浏览器访问 /api/sso/authorize
  -> 平台校验项目登记、回调地址和平台会话
  -> 仅回跳到已登记地址并附带一次性 code/state
  -> 项目后端 POST /api/sso/token 兑换身份
  -> 项目建立自己的 HttpOnly 会话
```

平台授权地址：

```text
GET /api/sso/authorize?project_id=<PROJECT_ID>&redirect_uri=<REGISTERED_URI>&state=<PROJECT_STATE>
```

项目兑换地址：

```text
POST /api/sso/token
Authorization: Bearer <PROJECT_CLIENT_SECRET>
Content-Type: application/json
```

请求体：

| 字段 | 规则 |
| --- | --- |
| `grant_type` | 固定为 `authorization_code` |
| `code` | 回调收到的一次性授权码 |
| `project_id` | 已登记项目标识 |
| `redirect_uri` | 必须与授权时完全一致 |

当前项目登记配置格式为 `project_id|client_secret|enterprise_id|redirect_uri`，每行一条；同一项目可登记多个回调地址，但项目凭证和企业绑定必须一致。平台必须拒绝：未知项目、项目凭证错误、企业未映射、回跳地址未登记、授权码过期、授权码重复消费、平台会话失效和用户/企业映射不一致。

授权码有效期为 60 秒且只能使用一次，不能把平台 Session、New API Key 或长期 Token 放进 URL。兑换接口只返回 `project_id`、`enterprise_id` 和 `subject`；业务项目据此建立自己的 HttpOnly 会话，平台 Session 不跨域共享。

## 5. 接入完成条件

一个项目只有同时满足以下条件，才算完成接入：

- 平台已登记项目标识、项目凭证、模型/功能白名单和回跳地址；
- 项目后端已从业务会话推导企业标识，并经 bridge 完成一次调用；
- 企业对应独立的平台计费账户，且余额和用量可审计；
- 项目页面已提供充值和消费记录入口；
- 若启用 SSO，已完成授权码过期、重放、越权回跳和企业隔离验证。

仅配置 bridge、仅出现普通跳转链接，或仅能返回模型结果，都不能宣称“自动具备入口和 SSO”。

## 6. 当前未实现边界

以下内容仍需单独实现和验收：

- 平台侧项目登记和回跳地址管理后台（当前为受控环境变量）；
- 项目用户到平台计费账户的持久化映射；
- SSO 撤销、登出联动和正式多项目部署。
