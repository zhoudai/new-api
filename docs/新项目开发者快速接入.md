# 新项目开发者快速接入 AI 平台

本文面向业务项目后端开发者。目标是：拿到平台配置后，用最少步骤完成一次安全的模型调用。

项目凭证由平台管理员通过[项目凭证管理 API](项目凭证管理.md)签发。企业充值和账单使用平台分配的企业用户名、密码登录，本期无需免密 SSO。

## 1. 先确认平台管理员已提供

通过 Secret 或安全渠道获取以下信息，不要把项目凭证写入前端、移动端、小程序或 Git：

| 配置 | 示例 | 用途 |
| --- | --- | --- |
| `BRIDGE_BASE_URL` | `https://ai.example.com/bridge` | 项目接入地址 |
| `PROJECT_ID` | `project-example` | 项目标识 |
| `PROJECT_CREDENTIAL` | `<SECRET>` | 项目后端访问凭证 |
| `ENTERPRISE_ID` | `enterprise-example` | 当前企业标识 |
| `FEATURE` | `analysis` | 当前业务功能标识 |
| `MODEL` | `deepseek-v4-flash` | 已开放的模型名称 |

平台管理员还需要完成：

- 为企业创建独立的平台计费账号和余额；
- 为项目配置企业映射和模型/功能白名单；
- 为当前项目部署独立 bridge 实例；
- 提供可追溯的项目登记信息。

当前 POC 的 bridge 是配置驱动的，一个实例绑定一个项目。新增项目时应部署新的实例，不要覆盖已有项目配置。

## 2. 在项目后端保存配置

以下变量只放在项目后端 Secret 或本机忽略配置中：

```dotenv
AI_PLATFORM_BRIDGE_BASE_URL=https://ai.example.com/bridge
AI_PLATFORM_PROJECT_ID=project-example
AI_PLATFORM_PROJECT_CREDENTIAL=<PROJECT_CREDENTIAL>
AI_PLATFORM_ENTERPRISE_ID=enterprise-example
AI_PLATFORM_FEATURE=analysis
AI_PLATFORM_MODEL=deepseek-v4-flash
```

其中 `AI_PLATFORM_ENTERPRISE_ID` 必须由项目后端根据登录会话和业务权限推导，不能直接信任浏览器提交的值。

## 3. 先做健康检查

```bash
curl --noproxy '*' "$AI_PLATFORM_BRIDGE_BASE_URL/health/ready"
```

预期返回：

```json
{"status":"ready"}
```

健康检查失败时，先联系平台管理员检查 bridge、平台服务和反向代理，不要继续排查业务代码。

## 4. 发起第一次模型调用

业务项目后端只调用 bridge，不直接调用上游模型或 New API 内部地址：

```bash
curl "$AI_PLATFORM_BRIDGE_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $AI_PLATFORM_PROJECT_CREDENTIAL" \
  -H "Content-Type: application/json" \
  -H "X-AI-Project-Id: $AI_PLATFORM_PROJECT_ID" \
  -H "X-AI-Enterprise-Id: $AI_PLATFORM_ENTERPRISE_ID" \
  -H "X-AI-Feature: $AI_PLATFORM_FEATURE" \
  -H "X-Request-Id: project-test-001" \
  -d '{
    "model": "deepseek-v4-flash",
    "messages": [{"role": "user", "content": "请返回：AI 平台接入成功"}],
    "stream": false
  }'
```

请求头规则：

| 请求头 | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | 项目凭证，不是企业内部 New API Key |
| `X-AI-Project-Id` | 是 | 已登记的项目标识 |
| `X-AI-Enterprise-Id` | 是 | 服务端确认后的企业标识 |
| `X-AI-Feature` | 是 | 服务端固定的功能标识 |
| `X-Request-Id` | 否 | 用于项目日志与平台扣费日志关联 |

## 5. 接入完成验收

平台管理员和项目开发者共同确认：

- [ ] 健康检查返回 `ready`；
- [ ] 模型调用返回成功结果；
- [ ] 平台日志能按项目、企业、模型和请求号查到调用；
- [ ] 企业余额产生正确扣减；
- [ ] 无效模型或无额度请求不会产生错误扣费；
- [ ] 浏览器网络请求中没有项目凭证、New API Key 或上游模型 Key。

常见状态码：

| 状态码 | 含义 | 优先检查 |
| ---: | --- | --- |
| `400` | 标识格式或请求参数错误 | 项目、企业、功能标识和请求体 |
| `401` | 项目凭证错误 | `Authorization` 是否使用项目凭证 |
| `403` | 项目或企业未开通 | 项目登记、企业映射和额度 |
| `404` | 路径不允许 | 是否调用 `/v1/*` |
| `502` | 平台上游不可用 | 平台渠道和平台服务状态 |

## 6. 需要充值、用量入口或 SSO 时

项目自己的页面负责展示充值入口和消费记录；平台只提供额度、用量和审计能力。普通跳转和第一版 SSO 的完整约束见：

- [`项目统一接入协议-v1.md`](项目统一接入协议-v1.md)
- [`项目接入与企业用户操作手册.md`](项目接入与企业用户操作手册.md)

当前 SSO、项目登记和企业映射仍有受控配置及人工验收环节，不能把一次 API 调用成功视为生产接入全部完成。
